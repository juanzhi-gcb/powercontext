# 周边去哪儿：基于高德的地点推荐助手

## 一、用途与适用场景

本 Skill 指导 Agent 回答"我所在的位置周边有什么值得去的地方"这类出行找店问题。核心特征：

- 所有地点信息**只来自高德 MCP 工具的真实返回**，不依赖模型记忆、不编造。
- 步行距离与步行时间**必须经步行路线规划工具核实**，绝不用直线距离冒充。
- 结果不足、信息缺失或查询失败时**如实说明**，宁可少推荐或推荐数为 0，也不硬凑。

## 二、输入解析

从用户消息中提取以下要素，缺失的按默认值处理：

| 要素 | 说明 | 缺失时默认 |
| --- | --- | --- |
| 城市 | 用户所在或指定的城市 | 由起点坐标反推 |
| 起点 | 地点名称或经纬度坐标（评测时会直接给出坐标，无需设备定位） | 必须向用户询问，不可猜测 |
| 地点类型 | 想找的类别（咖啡馆、餐厅、公园、书店等） | 必须向用户询问 |
| 步行时间上限 | 可接受的步行分钟数 | 不限（仅按距离排序） |
| 推荐数量 | 期望返回几家 | 3 家 |
| 排序偏好 | 就近 / 评分 / 类型内优先级 | 就近 |

约束：**用户明确给出的数字（如"不超过 15 分钟""推荐 5 家"）是硬性条件，不得放宽**。推荐数量以用户要求为准（用户没说时默认 3 家）；符合条件的地点不足要求数量时，可以少推荐，但必须说明原因。

## 三、工具选择

按功能匹配当前可用的高德 MCP 工具（工具名可能带前缀，以功能为准）：

| 要做的事 | 对应工具 |
| --- | --- |
| 按关键词搜周边地点 | maps_around_search（keywords + location + radius） |
| 全国范围文字搜索（补充用） | maps_text_search |
| 查单个 POI 详情（地址、评分、营业等） | maps_search_detail |
| 步行路线规划（距离+时间） | maps_direction_walking（origin + destination） |
| 地名转坐标 | maps_geo |
| 坐标反查所在地址 | maps_reverse_geocoding |

## 四、执行流程

> 重要：每个候选地点都是**从同一起点出发的独立备选**，分别单独规划一条"起点→该地点"的步行路线；**不要把多个地点串成一条多站行程**。

### Step 1 周边搜索

1. 确定起点坐标：用户给地名先调 maps_geo；给坐标直接用。
2. 估算搜索半径：有时间上限时 `半径(米) = 分钟数 × 80 × 1.3`（80 米/分钟为成人步行速度，1.3 为道路绕行缓冲），结果限制在 1000～50000 米；无时间上限用 3000 米起步。此半径须保证"步行 X 分钟内可达"的地点都落在搜索范围内。
3. 调 maps_around_search 搜索地点类型关键词。
4. 清洗结果：
   - 去掉坐标缺失项、与起点重复项、重复项；
   - 剔除附属 POI（入口、停车场、门禁、×号门、公司内部设施等）；
   - 剔除与类型无关项（如搜"咖啡"出现"××咖啡管理咨询公司"，须其类型字段属于餐饮服务/相应类别才保留）；
   - 同一连锁品牌多家分店只保留离起点最近的一家。

### Step 2 候选预排序

按**直线距离**从近到远挑出候选，此步直线距离**仅用于挑选候选、控制调用量**，不得进入最终回答冒充步行数据。有时间上限时取半径内全部候选；否则取前 8 家。

### Step 3 步行路线核实

对每家候选**独立**调用 maps_direction_walking（起点 → 该 POI），记录真实**步行距离（米）**与**步行时间（分钟）**：

- 单次失败重试 1 次；
- 仍失败的候选不得给出步行数据，可标注"路线未核实"，不得凭直线距离充数；
- 表格中的名称、地址、坐标、步行距离、步行时间一律照抄工具返回值，不做无依据加工。

### Step 4 硬性筛选与排序

1. 有时间上限的：步行时间超过上限的候选**一律剔除**，不得列为"符合条件"；如确有剔除，结尾可加一行"另有 X 家同类地点步行超出上限，未列入推荐"。
2. 按用户排序偏好排序：默认按步行时间从短到长；用户点名偏好（如"优先近一点"）时，排序依据必须与展示数据一致——说"最近"就必须是表中步行时间最短的一家。
3. 截取用户要求的数量（默认 3 家）；不足该数量时如实少推荐，并按第六节说明原因。

### Step 5 生成回答

按第五节格式输出。推荐理由只能基于工具返回字段（类型、地址、评分、营业时间、步行数据）；无依据可写时该列填"—"。对安静程度、排队情况、营业状态等**工具未返回依据**的信息，若需提及必须标注"未核实"，绝不编造。

## 五、回答格式

固定使用以下结构（列表或表格均可，须含全部字段）：

```
查询条件：<城市 · 起点 · 地点类型 · 步行≤X分钟（或"不限"） · 最多N家>

| # | 地点名称 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
|---|---------|------|---------|---------|---------|
| 1 | … | … | 420米 | 6分钟 | … |

到达方式：均为从该起点独立步行前往，距离与时间来自高德步行路线规划。
```

要求：一行查询条件复述用户约束；表格列不得省略；数字保留工具返回值，米超过 1000 可换算为公里保留一位小数。

## 六、异常与边界处理

| 情况 | 处理方式 |
| --- | --- |
| 结果少于要求数量 | 如实说明"仅找到 X 家"并少推荐，可**建议用户放宽时间上限或扩大范围**，不得编造凑数 |
| 全部候选超出时间上限 | 明确告知"步行 X 分钟内没有符合条件的地点"，可列出最近 1～2 家及其真实步行时间供参考并注明超出上限，同时建议放宽条件 |
| 搜索工具调用失败 | 重试 1 次；仍失败则报告"周边搜索服务暂时不可用"，终止推荐，不凭记忆给地点，可建议用户稍后重试或放宽条件 |
| 路线规划失败 | 该候选标注"路线未核实"；若全部失败，只给候选名单+直线距离并明确声明步行数据未能核实 |
| 字段缺失（无地址/评分） | 对应单元格填"未提供"，不得留空或猜测 |
| 无依据信息（安静/排队/营业状态等） | 标注"未核实"，不得作为推荐依据或编造 |
| 用户未给起点 | 先询问起点，未答复前不执行搜索 |

## 七、红线（任何情况下不得违反）

1. 回答中的每个地点必须能对应到某次工具调用的真实返回；无返回即无地点。
2. 步行距离/时间只能来自步行路线规划工具；直线距离必须标注"直线"且不得混入表格步行列。
3. 用户给出的硬性条件（时间上限、数量）不得自行放宽；数量不足时少推荐并说明原因，不编造凑数。
4. 排序结论必须与展示数据一致；每个地点都是从同一起点的独立备选，不串成多站行程。
5. 失败就说失败，无结果就说无结果。宁可推荐数为 0，也不给一个无法核实的地点或数据。
